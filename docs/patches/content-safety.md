# V3 补充设计：公共朋友圈内容安全防护

> 独立补丁，同样不改动 `moments-backend.zip`。

---

## 0. 先分清楚两种风险敞口，防护力度不一样

| 场景 | 风险敞口 | 现有防线 |
|---|---|---|
| AI主动发动态（post_moment, scope=public） | 低——已经设计成"public默认要弹确认卡片人工同意" | ✅ 已有，见V3第6节 |
| AI自动评论好友的动态（should-comment走llm_decide） | **高**——量大、她不会逐条看，`reply_mode=llm_decide`时是AI自主发出去的，没人把关 | ❌ 目前没有，这份补丁主要补这里 |

所以这份补丁的重点是给"自动评论"这条链路加一层内容审查，主动发动态那条链路维持现状就够。

---

## 1. 四层防护（从行为引导到硬性拦截）

### 第0层：Prompt层面的基调设定（行为引导，不是技术拦截）
在AI生成公共朋友圈内容/评论的system prompt里明确写：
- 不对他人的观点、外貌、能力做负面评判
- 不涉政治、宗教等敏感对立话题
- 玩笑/吐槽类内容要留有余地，避免阴阳怪气式表达
- 拿不准语气是否合适时，宁可只点赞不评论

这一层不保证100%有效（模型偶尔会跑偏），所以下面还需要技术层兜底。

### 第1层：关键词/敏感词过滤（最简单，兜底用）
维护一个基础敏感词/攻击性词汇表，公共内容发布/评论前过一遍，命中直接拦截。
这层粗暴但便宜、延迟低，先挡掉最明显的。

### 第2层：二次内容审查调用（关键新增）
在真正推送/发布public内容之前，**单独再调一次AI**，但这次不是"要不要评论"的决策，
而是纯内容安全判断，类似：

```
你即将审查一段将要公开发布的文字。判断它是否可能：
1. 冒犯、贬低、嘲讽某个具体的人
2. 涉及政治/宗教/地域/性别等易引发对立的敏感话题
3. 语气明显不友善

只回答 SAFE 或 FLAGGED，不需要解释。

待审查内容：{content}
```

**这个调用和"要不要评论"的决策调用是分开的两次AI调用，职责不同：一个决定说不说，
一个把关说的内容干不干净**——两件事混在一起容易漏判。

`FLAGGED`的处理：**不是直接拦截报错**，而是自动降级成"只点赞，不发送这条评论文字"，
用户体验上不会卡住流程，只是安静地不说话。

### 第3层：事后可追溯 + 撤回窗口
- 所有public动态/评论都记一份审计日志（`public_audit_log`表，见下），随时能查"AI这周在外面说了什么"
- 提供撤回接口：发布后一段时间内（比如30分钟）可以一键软删除并广播墓碑，
  即使已经推送出去，至少能尽快消掉，好友那边缓存也会同步标记删除

## 2. 数据结构新增

```sql
-- 敏感词表（第1层用，可以自己维护，也可以后续接第三方词库）
CREATE TABLE blocked_keywords (
  keyword TEXT PRIMARY KEY
);

-- 公共内容审计日志（第3层用，所有public动态/评论都记一份）
CREATE TABLE public_audit_log (
  id TEXT PRIMARY KEY,
  content_type TEXT NOT NULL CHECK(content_type IN ('moment','comment')),
  content TEXT NOT NULL,
  target_moment_id TEXT,           -- comment时填写，关联的动态
  moderation_result TEXT NOT NULL CHECK(moderation_result IN ('safe','flagged_downgraded','keyword_blocked')),
  created_at INTEGER NOT NULL
);
```

## 3. 接口层改动提示（给 Claude Code）

在 `services/replyControl.js` 的 `decideAction()` 返回 `ask_llm` 之后，
**新增一步**：聊天后端拿到AI生成的评论文字后，发布前先调 `/internal/moderate-content`
（新增接口），过关键词表+二次AI审查，`FLAGGED`或命中关键词就把这次动作降级为纯点赞，
`SAFE`才真正调用 `/api/moments/action` 发出去。

`post_moment`（主动发动态）那条链路本来就有人工确认弹窗，可以选择性地也在弹窗里
把审查结果标出来（比如"这条内容审查通过/建议再看看"），当作辅助提示给你自己判断，
但不强制拦截——因为这条链路本来就有你人工把关了。

---

## 4. 一点提醒

这套设计能挡掉大部分"明显不合适"的内容，但审查本身也是AI判断，不是100%保险。
如果你特别在意某个具体好友圈子的观感，可以在**第0层prompt**里针对那个场景加更严格的措辞，
或者干脆把对那个圈子的`reply_mode`设成`like_only`，从源头上减少AI自主发言的机会——
这跟之前防刷屏的思路是一回事：**能少说话就少说话，永远是最安全的默认值。**
